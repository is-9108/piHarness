# レビュー観点チェックリスト

## requirements（要件充足）
- [ ] Issue の受け入れ条件がすべてテストで検証されている
- [ ] 承認済みプランから逸脱していない（逸脱がある場合は理由が妥当か）
- [ ] スコープ外の変更（ついでのリファクタ等）が混ざっていない

## correctness（正しさ）
- [ ] 境界値（0, 1, 最大値, 空, null/undefined/None）
- [ ] エラー時の振る舞い（例外の握りつぶし、エラーの伝播、リトライの有限性）
- [ ] 非同期処理・並行処理（await 漏れ、競合、タイムアウト）
- [ ] リソース解放（ファイル・ソケット・プロセス・タイマー・GPIO）
- [ ] 時刻・タイムゾーン・文字コード

## tests（テスト品質）
- [ ] 実装の詳細ではなく振る舞いを検証している
- [ ] 異常系・境界値のテストがある
- [ ] テストが独立している（順序依存・共有状態・実時間/ネットワーク依存がない）
- [ ] モックが過剰でなく、本物の振る舞いと乖離していない
- [ ] アサーションが意味を持つ（常に真になる・何も検証しないテストがない）
- [ ] テストをスキップ/削除/弱めて合格させていない

## security（セキュリティ）
- [ ] 外部入力の検証
- [ ] シェルコマンド・SQL・パスの組み立てにインジェクションの余地がない
- [ ] 秘密情報（トークン・パスワード）をコード・ログ・リポジトリに含めていない
- [ ] ファイル権限・実行ユーザー（root 前提になっていないか）

## performance（性能・リソース / Raspberry Pi 5）
- [ ] メモリ使用量（大きなファイルの全読み込み、無制限のキャッシュ）
- [ ] CPU（ビジーループ、短すぎるポーリング間隔）
- [ ] ストレージへの頻繁な書き込み（SD カードなら寿命に直結。ログ・DB のバッチ化、tmpfs の検討）
- [ ] 起動時間、依存ライブラリのサイズ、arm64 (aarch64) 向けビルド・バイナリの有無
- [ ] 常時高負荷による発熱・サーマルスロットリング（Pi 5 はアクティブクーラー前提か）
- [ ] GPIO を使う場合、Pi 5 の RP1 チップでは旧来の RPi.GPIO / sysfs が使えない（libgpiod / gpiozero / lgpio を使う）

## maintainability（保守性）
- [ ] 命名が意図を表している
- [ ] 関数・モジュールの責務が単一
- [ ] 既存のパターン・ユーティリティを再利用している（重複実装がない）
- [ ] コメントは「なぜ」を説明している

## operability（運用性）
- [ ] ログが障害調査に十分で、過剰でない
- [ ] エラーメッセージが利用者に行動を示している
- [ ] 設定値のハードコードがない
- [ ] 既存データ・設定との後方互換性
