# バグ修正フロー（piHarness）

実装フローとは独立して、**1 つのバグ**だけに集中して根本原因を潰すためのフローです。
**独立したセッション**で実行され、実装フローの会話は引き継がれません。入力は開始メッセージに列挙された成果物
（`escalation-N.md`, 直近のテストログ, `issue.md`, `plan.md`, `implementation.md`, 直近の `review-N.md`）だけです。
エスカレーションから起動された場合、中断中の実装フローは退避されており、完了後に**新しいレビューセッション**で合流します（`harness_status` の「合流予定の実装フロー」で確認可能）。
合流後のレビュー担当は `bug-N.md` を読んで状況を把握するため、バグレポートは他人が読んで分かるように書いてください。

```
bug_reproduce ─(再現確認 red)→ bug_analyze ─→ bug_fix ─(全テスト green)→ bug_done ─→ 実装フロー impl_review へ合流
                                  ▲               │
                                  └───────────────┘ 失敗: 再分析（連続3回失敗でエスカレーション）
```

## 0. 状況の把握

1. バグの説明と入力成果物をすべて読む（特に `escalation-N.md` の「経緯」と直近のテストログ）。
2. `templates/bug-report.md` を元に、開始メッセージで指定された **`bug-N.md`**（作業ディレクトリ内）を作成し、症状・再現手順・期待/実際の動作・これまでの試行を書く。
3. 症状や期待動作が不明確なら `harness_ask` でユーザーに確認する。

## 1. 再現（bug_reproduce）

1. バグを再現する**最小のテスト**を書く（既存の失敗テストがバグを正確に表していればそれを使ってよい）。
2. `harness_run_tests`（`expect: "red"`）で失敗することを確認する。
   - 合格してしまう場合は再現できていない。条件を見直す。
   - 環境依存（ラズパイ固有のハードウェア、タイミング、メモリ不足）が疑われる場合は、その条件をテストで再現する方法（モック・注入）を考える。
3. `harness_phase` で `bug_analyze` へ（note に再現条件）。

## 2. 根本原因の分析（bug_analyze）

この段階ではコードを変更しません（拡張がブロックします）。

1. 症状から原因までを**因果関係の連鎖**として説明できるまで調べる（ログ追加が必要ならバグレポートに「確認方法」として書き、修正フェーズで行う）。
2. これまでの修正が失敗した理由（実装フローでの試行）も分析する。同じ仮説を繰り返さない。
3. 「なぜ既存のテスト/レビューで見逃したか」も記録する。
4. 修正方針を決め、影響範囲（他の呼び出し元）を洗い出す。
5. バグレポートを更新し、根本原因と修正方針をユーザーに簡潔に共有してから `harness_phase` で `bug_fix` へ。

## 3. 修正（bug_fix）

1. 根本原因に対する**最小限の修正**を行う。症状を隠すだけの修正（例外の握りつぶし、テストの条件緩和、リトライで誤魔化す）はしない。
2. `harness_run_tests`（`expect: "green"`）で**全テスト**を合格させる（再現テストを含む）。
3. 失敗した場合は、再び原因分析からやり直す（必要なら `harness_phase` で `bug_analyze` に戻る）。連続 3 回失敗するとユーザーへ再エスカレーションされます。
4. 合格したら、同じ原因の類似箇所が無いか確認する（見つけたら報告し、修正するかはユーザーに確認）。
5. バグレポート `bug-N.md` に修正内容と追加したテストを記録する（無いと `bug_done` へ進めません）。
6. `harness_phase` で `bug_done` へ。

## 4. 完了と合流（bug_done）

- 合流先の実装フローがある場合、ユーザーの確認後に**新しいセッション**で `impl_review`（フルレビュー）から再開します。このセッションでは短く報告して終了してください。
- ユーザーが合流を保留した場合は、状況を報告して待機する（ユーザーは後で `/harness rejoin` で合流できる）。
- 単独起動の場合は、根本原因・修正内容・追加テストを報告して終了。
