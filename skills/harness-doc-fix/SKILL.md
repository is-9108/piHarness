# ドキュメントのレビュー指摘修正

## 共通ルール

- このセッションは 1 つのプロセスだけを担当する。前のプロセスの会話は無い。開始メッセージの**入力成果物を最初に読み**、推測で補わない。
- 次のプロセスが必要とすることは**すべて出力成果物に書く**。
- フェーズ遷移は harness_* ツールで行う。承認ゲート・ループ上限を迂回しない。「プロセス完了」と返されたら作業をやめ、成果を 1〜3 文で報告して終了する。
- **ドキュメントだけを扱う。** コード・テスト・設定ファイルは変更しない（ブロックされ、レビュー前にも git の差分で確かめられる）。テストは実行しない。
- 自分でコミット・push・ブランチ操作をしない。

## 手順

1. 最新の `review-N.md` のブロッキング指摘（blocker/major）を読む。背景が必要なときだけ `doc-report.md` / `outline.md` を参照する。
2. 指摘ごとに直す。直した内容はコード・情報源で確かめる。指摘が誤っていると判断したら、根拠を `fix-N.md` に書く（黙って無視しない）。
3. `templates/fix-report.md` に従い **`fix-N.md`**（N = レビュー周回）を書く。**次のレビューは主にこれと前回からの差分を見る**ので、新たに変更した箇所も書く。
4. `harness_phase` で `doc_review` へ（`fix-N.md` が無い、ドキュメント以外のファイルが変わっている場合は拒否される）。
